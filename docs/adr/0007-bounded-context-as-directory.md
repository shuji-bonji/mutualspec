# ADR-0007: 境界: コンテキスト = ディレクトリ + コード、越境は宣言した経路だけ

- 状態: Accepted
- 日付: 2026-11-19

## 状況

DDD の境界づけられたコンテキストは「言葉の意味が統一されている範囲」。会話第 3 回で「範囲の限定」が相互理解の条件とされ、第 4 回で LLM は境界をまたぐときは明示的な変換を経たデータだけを見るべきとされた。

## 決定

- `specs/<path>/` の 1 ディレクトリ = 1 コンテキスト。すべての要素 ID とモジュールはコンテキストコードを持つ。
- 越境参照は context-map の relation の向き（下流 → 上流、partnership / shared-kernel は双方向）に沿い、published な要素（published 用語、interface、published イベント、`via` に列挙した要素）に限る。
- トレース用の参照は published でなくてよい（向きの制約は適用）。
- published 用語の禁止語は下流にも適用される。

## 検討した代替案

- タグでコンテキストを表す: 1 要素が複数コンテキストに属しうる曖昧さが残る。
- 越境を自由にし、警告だけ出す: 境界の意味がなくなる。

## 結果

- 上流のインターフェース変更は上流のループで行い、下流は別ループで追随する。
