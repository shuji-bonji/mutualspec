# ADR-0008: 判定は決定的なツール、LLM は提案、LLM レビューは助言

- 状態: Accepted
- 日付: 2026-11-19

## 状況

会話第 3 回: LLM は構造を無視して自然言語で答えることがあり、出力後の検証を必須にしないと相互理解が崩れる。

## 決定

- 合否判定（ゲートの機械条件）は L0〜L4 の決定的なバリデータだけが行う。
- LLM の出力は Change Proposal（JSON Schema）として受け取り、`specloop apply` が検証してから決定的に書き込む（既定）。Direct-edit モードでも成果物は同じ検証を通る。
- LLM のレビュー（L5）は advisory で、単独ではゲートを失敗させない。
- MCP サーバーは判定結果を返し、判定そのものを LLM に委ねない。

## 検討した代替案

- LLM に合否を判定させる（LLM-as-a-judge をゲートに使う）: 非決定的で、再現・監査できない。
- LLM に正本を自由に書かせる: 差分の責任と範囲が曖昧になる。

## 結果

- 機械で判定できない特性（feasible、correct）は narrative ルールとして人のレビューに残る。
