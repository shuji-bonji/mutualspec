# ADR-0006: BREX を超える意味モデル層を独立させる

- 状態: Accepted
- 日付: 2026-11-19

## 状況

会話第 2・3 回: BREX は文書の構造ルールであり、業務プロセスの順序・判断ロジック・「なぜそのルールがあるか」・現場での判断を持てない。この限界を別の明示的なモデルで補えば、人と LLM が相互に理解できる文書になる。

## 決定

- 意味モデル層を構造層・語彙層とは別に置く: 不変条件（INV）、状態遷移（BHV）、判断表（DEC）、理由（rationale、要求と不変条件で必須）、判断点（JDG）、適用性。
- 文書（procedure）は判断表を**参照**し、判断ロジックを本文に持たない。
- 判断点は機械も LLM も決めない。判断結果を記録し、フィードバックとして判断表に昇格させる経路を持つ。
- 意味モデル層の要素は検査可能にする（状態遷移の到達性、判断表の重複・漏れ）。

## 検討した代替案

- 業務ロジックを手順文や BREX の narrative に書く: 機械で検査できず、LLM が推測で補う。
- BPMN / 完全な DMN を採用: 表現力は高いが重く、仕様の正本として人と LLM が読むには過剰。交換形式として将来連携する。

## 結果

- 仕様を書く量が増える（R-01）。意味モデル層は「現場で判断が分かれる点」に限る運用指針を置いた。
